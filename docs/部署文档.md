## 架构概览

Anchor Memory 包含两个接口，通过 `entrypoint.sh` 在同一个容器内运行：

| 组件 | 文件 | 职责 | 内部端口 |
|------|------|------|------|
| Web Dashboard | `anchor_web.py` | Flask 管理界面 | 8000 |
| MCP Server | `anchor_mcp.py` | MCP 协议服务 + 定时 dream pass | 8001 |

`both` 模式由 `anchor_server.py` 创建唯一的 `AnchorMemory` 实例，并在同一 Python 进程中同时提供两个接口：Waitress 在线程中监听 8000，FastMCP 在主线程监听 8001。这样不会让两个进程同时打开同一个本地 Chroma 持久化目录。

### 部署模式

通过 `ANCHOR_MODE` 环境变量控制：

| 模式 | 说明 | 启动的服务 |
|------|------|-----------|
| `both`（默认） | 同时启动 Web + MCP | Dashboard :8000 + MCP :8001 |
| `web` | 仅 Dashboard | Web :8000 |
| `mcp` | 仅 MCP Server | MCP :8001 |

> Docker 部署默认 `ANCHOR_MODE=both`。Web 与 MCP 共享同一个 `AnchorMemory`/Chroma 客户端；不要改成两个独立进程访问同一个 `/app/anchor_data/chroma`。

## 环境变量

在 `.env` 文件或 Docker 环境中配置：

```bash
# ── Dashboard ──
# 纯数字密码，留空则 Dashboard 无需密码
ANCHOR_DASHBOARD_PASSWORD=

# ── MCP Server ──
# Bearer token 认证，留空则不启用认证
ANCHOR_API_KEY=
# 传输模式: stdio 或 streamable-http
ANCHOR_TRANSPORT=streamable-http
# 监听端口（仅影响 MCP Server）
ANCHOR_PORT=8001

# ── LLM 配置 ──
# 为空则后台 LLM 功能降级为粗匹配
ANCHOR_LLM=openai-compat/deepseek-v4-flash
ANCHOR_LLM_API_KEY=
ANCHOR_LLM_ENDPOINT=https://api.deepseek.com/v1
```

完整示例见 `.env.example`。

## 本地开发

### 前置条件

- Python 3.11+
- 建议 GPU（首次加载 embedding 模型约 470MB）

### 安装

```bash
# 克隆仓库
git clone <repo-url>
cd anchor-memory

# 创建虚拟环境
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

首次启动会自动下载 `paraphrase-multilingual-MiniLM-L12-v2` 模型。

### 启动 MCP Server（stdio 模式）

适用于 Claude Code、Cursor 等本地 MCP 客户端：

```bash
python anchor_mcp.py --db-path ./anchor_data
```

### 启动 MCP Server（HTTP 模式）

适用于 Kelivo 等远程 MCP 客户端：

```bash
python anchor_mcp.py \
  --db-path ./anchor_data \
  --transport streamable-http \
  --host 0.0.0.0 \
  --port 8001
```

### 启动 Web Dashboard

```bash
python anchor_web.py --db-path ./anchor_data --host 0.0.0.0 --port 8000
```

访问 `http://localhost:8000`，密码由 `ANCHOR_DASHBOARD_PASSWORD` 控制。

### 同时启动 MCP + Web

```bash
# macOS / Linux
ANCHOR_MODE=both ./entrypoint.sh

# 或手动分别启动（注意用不同端口）
python anchor_web.py --db-path ./anchor_data --host 0.0.0.0 --port 8000 &
python anchor_mcp.py --db-path ./anchor_data --transport streamable-http --host 0.0.0.0 --port 8001
```

## Docker 部署

### 快速启动

```bash
# 构建并启动（默认 both 模式）
docker-compose up -d

# 查看日志
docker-compose logs -f anchor
```

启动后：
- Web Dashboard: `http://localhost:8000/`
- MCP Server: `http://localhost:8001/mcp`

### Dockerfile 说明

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY *.py .
COPY web/ web/
COPY entrypoint.sh .
RUN sed -i 's/\r$//' entrypoint.sh && chmod +x entrypoint.sh

EXPOSE 8000 8001
ENTRYPOINT ["./entrypoint.sh"]
```

### 自定义配置

编辑 `.env` 文件后重启：

```bash
docker-compose down
docker-compose up -d
```

### 仅启动 MCP

```bash
docker-compose run -e ANCHOR_MODE=mcp -p 8001:8001 anchor
```

### 仅启动 Dashboard

```bash
docker-compose run -e ANCHOR_MODE=web -p 8000:8000 anchor
```

### 手动构建

```bash
docker build -t anchor-memory .

# both 模式
docker run -d \
  -p 8000:8000 \
  -p 8001:8001 \
  -v anchor_data:/app/anchor_data \
  -e ANCHOR_MODE=both \
  -e ANCHOR_DASHBOARD_PASSWORD= \
  -e ANCHOR_API_KEY=your-secret-key \
  -e ANCHOR_LLM=openai-compat/deepseek-v4-flash \
  -e ANCHOR_LLM_API_KEY=your-llm-key \
  -e ANCHOR_LLM_ENDPOINT=https://api.deepseek.com/v1 \
  anchor-memory
```

## Zeabur 部署

### 步骤

1. 在 Zeabur 中创建新服务，选择从 Git 仓库部署
2. 设置环境变量：

| 变量 | 值 | 必填 |
|------|-----|------|
| `ANCHOR_MODE` | `both` | 是 |
| `ANCHOR_DASHBOARD_PASSWORD` | 你的密码 | 否（留空免密码） |
| `ANCHOR_API_KEY` | MCP Bearer token | 否 |
| `ANCHOR_LLM` | `openai-compat/deepseek-v4-flash` | 推荐 |
| `ANCHOR_LLM_API_KEY` | DeepSeek API Key | 推荐 |
| `ANCHOR_LLM_ENDPOINT` | `https://api.deepseek.com/v1` | 推荐 |

3. 配置两个 HTTP 端口，并分别绑定域名：Dashboard 使用 `8000`，MCP 使用 `8001`
4. 添加持久化存储，挂载到 `/app/anchor_data`

### 注意事项

- 持久化存储必须挂载到 `/app/anchor_data`，否则容器重启后数据丢失
- `both` 模式的正常启动日志应同时包含 `Web Dashboard listening on 0.0.0.0:8000` 和 `MCP Server listening on 0.0.0.0:8001`
- 不要运行两个独立 Python 进程访问同一个本地 Chroma 数据目录

## MCP 客户端配置

### Claude Code / Cursor

在 MCP 配置文件中添加：

```json
{
  "mcpServers": {
    "anchor-memory": {
      "command": "python",
      "args": ["/absolute/path/to/anchor_mcp.py", "--db-path", "/absolute/path/to/anchor_data"]
    }
  }
}
```

### Kelivo（远程 HTTP）

连接地址：`http://<host>:8001/mcp`

如设置了 `ANCHOR_API_KEY`，需在 Kelivo 中配置 Bearer token。

> Zeabur 部署时，为端口 8001 单独绑定 MCP 域名，例如 `https://anchor-mcp.zeabur.app/mcp`。Dashboard 域名绑定端口 8000。

### 认证说明

- `ANCHOR_API_KEY` 为空 → 无认证，任何客户端可连接
- `ANCHOR_API_KEY` 设值 → MCP 请求需携带 `Authorization: Bearer <key>`
- 使用 MCP SDK 内置的 `StaticTokenVerifier`，不是 OAuth

## LLM 配置

LLM 用于 dream pass、concept link、记忆拆分等后台任务。不配置时核心功能（存储/搜索/Hebbian）仍可正常使用。

### 配置方式（优先级从高到低）

1. **Web Dashboard 设置面板** → 写入 `~/.anchor/config.yaml`
2. **环境变量** → `ANCHOR_LLM` + `ANCHOR_LLM_API_KEY` + `ANCHOR_LLM_ENDPOINT`
3. **Anthropic API Key** → 自动使用 Haiku

### 支持的 Provider

| Provider | ANCHOR_LLM 格式 | 需要额外配置 |
|----------|-----------------|-------------|
| Anthropic | `anthropic/claude-haiku-4-5-20251001` | `ANTHROPIC_API_KEY` |
| OpenAI | `openai/gpt-5-nano` | `OPENAI_API_KEY` |
| Google | `google/gemini-2.5-flash` | `GOOGLE_API_KEY` |
| DeepSeek | `openai-compat/deepseek-v4-flash` | `ANCHOR_LLM_API_KEY` + `ANCHOR_LLM_ENDPOINT` |
| Ollama | `openai-compat/llama3` | `ANCHOR_LLM_ENDPOINT=http://localhost:11434/v1` |

### 示例：DeepSeek 配置

```bash
ANCHOR_LLM=openai-compat/deepseek-v4-flash
ANCHOR_LLM_API_KEY=sk-xxxxxxxx
ANCHOR_LLM_ENDPOINT=https://api.deepseek.com/v1
```

## 数据目录结构

```
anchor_data/
├── memories.db          # SQLite 主数据库（记忆、边、评论、注解）
├── chroma/              # ChromaDB 向量索引
└── concept_cache.json   # 概念链接缓存（自动生成）
```

Docker 中对应容器内路径 `/app/anchor_data`。

### 备份

```bash
# 停止服务后直接复制
cp -r anchor_data/ anchor_data_backup_$(date +%Y%m%d)/
```

### Docker Volume 备份

```bash
docker run --rm -v anchor_data:/app/anchor_data -v $(pwd):/backup alpine \
  tar czf /backup/anchor_backup_$(date +%Y%m%d).tar.gz -C /app/anchor_data .
```

## 健康检查

Dashboard 提供无需认证的 `/health` 端点；MCP 可通过 8001 的 TCP 连接确认监听状态：

```bash
# Web Dashboard
curl http://localhost:8000/health
# {"status":"ok","total_memories":42,"index_count":42,"synced":true}

# MCP Server
python -c "import socket; s=socket.create_connection(('127.0.0.1', 8001), 3); s.close(); print('ok')"
```

## 常见问题

### 1. 首次启动很慢

使用远程 Embedding 时，启动会发送一次探测请求以确认模型维度。若需要从 SQLite 重建 Chroma 索引，还会逐条重新生成向量，耗时取决于记忆数量和服务商延迟。

### 2. `both` 模式只有一个端口可用

确认部署的是包含 `anchor_server.py` 的新镜像，并检查 `ANCHOR_MODE=both`。正常日志必须同时显示 8000 与 8001 的监听消息；如果只显示其中一个，不要把健康状态视为完整启动成功。

### 3. Kelivo 连接失败

- 确认使用 `streamable-http` 模式：`ANCHOR_TRANSPORT=streamable-http`
- 检查端口：MCP 默认 **8001**（不是 8000，8000 是 Dashboard）
- 如设置了 `ANCHOR_API_KEY`，确认 Kelivo 配置了相同的 Bearer token

### 4. Dream Pass 没有定时执行

- MCP Server 的 `streamable-http` 模式自动每 24 小时执行一次
- `stdio` 模式不启动定时任务，需手动调用 `dream_pass` 工具
- Web Dashboard 不会自动执行 dream pass
- 手动触发：在 Dashboard 点击 "Dream Pass" 按钮

### 5. LLM 相关功能报错

- 检查 `ANCHOR_LLM` 格式是否正确：`provider/model`
- `openai-compat` 必须同时配置 `ANCHOR_LLM_API_KEY` 和 `ANCHOR_LLM_ENDPOINT`
- 查看日志中的 `[Consolidate]` 或 `[ConceptLink]` 前缀信息

### 6. SQLite 锁定错误

已设置 `timeout=30.0`，正常使用不会出现。如仍遇到：

- 确认没有其他进程同时写入同一个数据库
- 检查磁盘空间是否充足
- WAL 模式已默认启用，支持并发读写

### 7. Dashboard 密码问题

- 环境变量 `ANCHOR_DASHBOARD_PASSWORD` 为空时免密码登录
- 设值后需输入对应密码
- Docker 中通过 `.env` 或 `-e` 参数设置

### 8. 数据迁移

从旧版升级时，新增的数据库字段（`internalized`、`context`、`visual_embedding`）会自动安全添加，无需手动迁移。

### 9. 端口说明

| 对外端口 | 路径 | 后端服务 | 用途 |
|----------|------|----------|------|
| 8000 | `/` | Web Dashboard | 浏览器访问的管理界面 |
| 8001 | `/mcp` | MCP Server | MCP 客户端连接（Kelivo 等） |

容器不再包含 nginx。Zeabur 应为 8000 和 8001 分别绑定域名；两个接口运行在同一 Python 进程中并共享唯一的 `AnchorMemory` 实例。
